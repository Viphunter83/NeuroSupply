## 0. Регистрация и управление доступом (Verified)

Система NeuroSupply построена по принципу **Zero-Configuration**. Сотрудникам не нужно настраивать интеграции или вводить API-ключи — всё управление правами доступа сосредоточено в руках Администратора.

### Процесс активации пользователя:
1.  **Самостоятельная регистрация**: Повар или менеджер заходит на сайт и нажимает кнопку **"Sign Up"**. 
    - *Важно:* В этот момент аккаунт пуст и не привязан к данным. Это "режим ожидания".
2.  **Активация (Admin)**: Администратор заходит в раздел **"Персонал"** (Staff).
    - Кабинет администратора позволяет идентифицировать новых сотрудников по **Email** (добавлен в v2.4.0 для удобства).
    - Выбирает роль: **Cook** (Повар) или **Manager** (Менеджер).
    - Привязывает пользователя к конкретному ресторану (например, **DNL**) в 1 клик.
3.  **Мгновенный доступ**: При следующем входе система автоматически подгружает данные iiko, остатки и рецепты именно для этой точки.

## 1. Архитектура и интеграция данных

Система NeuroSupply работает по модели **Pure Web**, исключая промежуточные звенья вроде Google Sheets.

*   **Интеграция с iiko:** Прямое взаимодействие через iiko Resto API. Система в реальном времени получает:
    *   Фактические остатки на складах (`StockBalance`).
    *   Технологические карты блюд (`EmpiricalRecipe`).
    *   Данные о продажах вчерашнего дня для обучения AI-модели.
*   **Движок расчета (Engine V2.1):** Находится на сервере, выполняет расчеты на основе БД, без внешних зависимостей.
*   **Монетизация (NeuroCredits):** Ресурсная модель. Каждый расчет AI списывает кредиты, баланс которых управляется на уровне аккаунта компании.

## 2. Роли и User Flow

Система разделена на два интерфейса для оптимизации ежедневной рутины.

### Режим Менеджера (Dashboard)
1.  **Настройка**: Привязка iiko API и Shop ID. Установка параметров `safety_stock` (страховой запас) и `days_in_transit`.
2.  **Планирование**: Ввод целевого плана выручки (на день/неделю/месяц). Это "двигатель" для AI-прогноза.
3.  **Контроль**: Просмотр аномалий списаний и подтверждение заказов, сформированных поварами.
4.  **Экспорт заявок**: Выгрузка финальной заявки в **Excel** за 1 клик для отправки поставщикам через почту или мессенджеры.

### Режим Оператора (Mini App / Повар)
1.  **Инвентаризация**: Ввод фактических остатков критических позиций (Stock Take).
2.  **AI-расчет**: Одним кликом запускается расчет. Процесс потребляет **NeuroCredits** (ресурсная модель ИИ).
3.  **Корректировка и Подтверждение**: Проверка и отправка черновика заказа менеджеру.

**Ежедневный цикл занимает ~5 минут:**
`Авто-синхронизация iiko` -> `Ввод остатков поваром` -> `AI-движок (Расчет)` -> `Excel Export менеджером`.

## 3. Алгоритм расчета "Money-to-Ingredient" (Шаг за шагом)

Логика системы NeuroSupply строится на декомпозиции финансовых целей в материальные потребности.

**Шаг 1: Прогнозирование (AI Forecast)**
Система берет план выручки (например, 150,000 руб.). AI-модель (`RandomForestRegressor`) анализирует день недели, исторические тренды и аномалии. 
*Результат:* Коэффициент спроса (например, 1.3). *Ожидаемая база потребления = 195,000 руб.*

**Шаг 2: Моделирование продаж (Product Mix)**
На основе статистики продаж система распределяет прогнозируемую сумму по конкретным блюдам меню.
*Пример:* На 195к руб. ожидается продажа 80 порций "Нэм 3 шт".

**Шаг 3: Взрыв техкарт (Recipe Explosion)**
Для каждого ожидаемого блюда "поднимаются" техкарты. 
*Пример:* 80 порций "Нэм" -> требуется 7.2 кг рисовой бумаги.

**Шаг 4: Расчет чистой потребности (Net Requirement)**
`Чистая потребность` = `(Прогноз + Страховой запас)` - `(Текущий остаток + Товар в пути)`.

**Шаг 5: Округление и упаковка**
Система приводит дробные цифры к складским единицам.
*7.64 кг* при упаковке по 0.3 кг -> **Заказ: 26 упаковок**.

## 4. Практический пример: Ресторан DNL (Кейс-стади)

Ниже приведен фрагмент реального расчета, демонстрирующий работу логики:

| Продукт | AI Спрос | Факт-остаток | Расчет (кг) | Заказ (Уп) | Логика системы |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **Бумага рисовая** | 1.3 | 0.25 кг | 7.64 | **26 шт** | Критичный дефицит под план 150к. |
| **Лапша Миен** | 1.3 | 2.99 кг | 2.15 | **0** | Запаса хватает. Заказ блокирован. |
| **Масло фритюрное**| 1.3 | 0.12 кг | 3.20 | **4 шт** | Пополнение до целевого уровня. |

**Результат внедрения:**
*   Исключение "стоп-листов" (всегда есть ингредиенты под план).
*   Снижение излишков на складе (блокировка лишних закупок, как в примере с лапшой).
*   Полная прозрачность: менеджер видит, *почему* система предлагает именно такой объем.

## 5. Работа в распределенной сети (Multi-Unit)

NeuroSupply — это единая платформа для управления сетью.
*   **Глобальный профиль:** Общий бюджет NeuroCredits и настройки брендов.
*   **Локальные Shop ID:** Каждый ресторан имеет свои уникальные остатки и планы, но управляется из одного окна.
*   **Централизация:** Собственник видит сводную аналитику по Food Cost и ошибкам персонала во всех точках одновременно.

## 6. Техническое соответствие (Technical Compliance)

Для технического аудита подтверждаем реализацию ключевых узлов:
- **Zero-Config Auth**: Реализовано в `src/api/v1/endpoints/auth.py` (метод `get_current_user`). Данные фильтруются автоматически по `linked_restaurant_id`.
- **Iiko Sync Engine**: Модуль `src/services/iiko/sync_service.py` выполняет прямой импорт `StockBalance` и техкарт без внешних посредников.
- **AI Analytics**: Модель `RandomForestRegressor` используется в `src/services/analytics/forecast.py` для вычисления `demand_coefficient`.
- **Excel Generation**: Эндпоинт `/api/v1/orders/{order_id}/export` формирует файл на лету на основе утвержденного заказа.
